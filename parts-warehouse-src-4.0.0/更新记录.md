## 2026-08-28 设计更新：日志库与 Excel-JSON 转换

已确认后续库存日志采用“**一次业务操作对应一个日志 Excel 文件**”的模型：

- 一次批量取出、批量入库或库存调整，不按物料明细拆成多个日志文件。
- 一个日志 Excel 文件保存该次操作的全部明细，使用标准仓库 Excel 行格式，便于查看、备份和逆向处理。
- 账单/主页报告按“操作集合”展示：默认只显示时间、动作和摘要；点击“展开”后显示该次操作对应的明细行，收起后恢复紧凑列表。
- 单项撤回、多项撤回、全体撤回，本质上都是读取对应日志 Excel，执行相反方向的库存操作，并记录新的撤回操作；不直接删除历史事实。
- 日志 Excel 既用于账单展示，也用于撤回时的快速数据来源，避免从已经变化的库存表反向猜测原始数据。
- 远端协作时，Excel 是本地业务数据/日志归档格式，JSON 是 Git 事件传输格式；两者之间必须经过明确的字段转换，不能把任意 JSON 直接当成库存 Excel。

当前代码已经具备结构化账本 `ledger.jsonl`、一次操作集中保存 `details[]`、本地/线上来源标识和 Git 事件读写基础；“日志 Excel 的正式落盘、JSON 应用到库存 Excel、按日志 Excel 执行撤回”作为下一阶段接入内容，转换约定见 `Excel-JSON转换手册.md`。

## 当前版本功能

### 元器件图片录入

- 图片先执行本地 OCR，再进行结构化整理。
- 标准 MLCC、电阻、电感等常见标签优先走本地规则。
- OCR 数量标签、封装误识别、采购料号断行和 EIA 电容编码冲突已有清洗与校验。
- 结构化结果保留 `source_image`，用于核对图片覆盖情况。
- 无法安全本地判断的复杂项才回退 AI。
- 不在测试阶段写入库存或 Excel。

### BOM 清单

统一名称为“BOM清单”，业务流程为：

```text
EDA BOM 导入
  -> 解析 BOM
  -> 仓库匹配
  -> 用户确认具体仓库物料
  -> 保存 BOM 清单
  -> 取出系统选择清单
  -> 输入生产份数
  -> 实时核验库存
  -> 用户确认后取出
```

BOM 清单是完整的 EDA BOM，不是只保存有库存的部分：

- 已匹配行保存具体仓库子分类、仓库行号和物料快照。
- 缺料行仍然保存，绑定字段留空。
- 缺料行状态为“未匹配/待补料”。
- 取出时缺料行不会自动扣库存。
- 库存补充后可以再次补选或重新匹配。
- 单板用量按生产份数放大：`取出数量 = 单板用量 × 生产份数`。
- 保存、读取、修改、删除 BOM 清单都不会修改库存。
- 只有用户确认取出后才调用库存扣减接口。

### BOM 清单 Excel 存储

BOM 清单不再使用 JSON 作为主存储，而是每份清单一个独立 Excel 文件：


### BOM 清单管理

首页和 BOM 清单匹配页均有 BOM 清单管理入口。

管理窗口支持：

- 查看已保存 BOM 清单列表。
- 查看清单全部行。
- 修改需求名称/型号、品牌、封装、单板用量和规格参数。
- 修改清单名称。
- 保存修改。
- 删除清单及对应 Excel 文件。
- 查看“已匹配”和“未匹配/待补料”状态。

管理 BOM 需求字段时不会自动改动已确认的仓库绑定。

## Git 增量库存同步研究

已确认新的多人协作设想：所有参与者基于同一个初始 `data` 快照，软件启动时只读取上次同步之后的库存变动事件；每次本地库存变动生成独立事件并上传 Git。Git 不作为完整库存表的多人覆盖存储，而作为增量事件、审计和同步来源。

推荐事件目录为 `events/年/月/日/<event_id>.json`，每次变动一个文件，避免多人同时追加同一个日志文件产生冲突。事件需要包含稳定 `part_id`、数量变化、变动前数量或版本、操作人、时间、原因和幂等请求 ID。

已记录的关键边界：Git 本身不提供库存事务；两个参与者基于同一旧库存同时取料时，后到事件必须通过 `quantity_before/base_revision` 校验，冲突时进入待处理状态，不能覆盖库存。第一版应先实现增量读取和事件重放，再实现事件提交；正式扣减最好由 Flask 统一校验后写入 Git。

详细方案见：`在线库存协作研究.md` 的“方案 E：Git 作为库存变动事件仓库”。你的使用场景是同一仓库、同一现场协作，因此同步触发点可以放在“使用仓库功能”内，而不是每秒后台轮询。进入库存浏览、元器件取出、入库或 BOM 取出前，先执行一次远端日志检查和增量同步；本地操作完成后再上传一条事件。


源码上传或制作发布包时应包含：

- `app.py`
- `warehouse/`
- `templates/`
- `static/`
- `tests/`
- `tools/`
- `requirements.txt`
- `README.md`
- 本更新记录
- `在线库存协作研究.md`

不要把以下内容当作源码上传：

- `dist/parts-warehouse/data/` 中的用户库存数据和 BOM 清单数据
- `build/`
- `build_release_onefile/`
- `share_dist/`
- `*.zip` 发布包
- `backups/`
- API key、认证信息和本地配置中的敏感凭据

发布前必须先备份完整工程目录；发布包中的程序文件更新不能覆盖用户已有 `data/` 数据。
