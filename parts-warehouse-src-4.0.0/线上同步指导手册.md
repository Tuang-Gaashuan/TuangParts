## 1. 同步是什么（30 秒看懂）

线上同步 = 把**库存变动事件**（不是整个 Excel）推送到一个 Git 远端仓库：

- 每次业务操作（录入 / 取出 / 调整）生成一条事件文件，存到仓库 `events/年/月/日/` 下
- 仓库里**永远没有**你的库存 Excel、没有设置文件、没有凭据
- 用途：多台电脑共享同一份事件流、异地备份、审计留痕

```text
Gitee / GitHub 远端仓库
└── events/2026/08/29/<event_id>.json   ← 一条账本记录 = 一个文件
```

## 2. 创建数据仓库

### 2.1 在 Gitee 创建（国内访问快，推荐主用）

1. 登录 [gitee.com](https://gitee.com)，右上角「+」→「新建仓库」
2. **仓库名称**：英文小写，例如 `parts-warehouse-sync`（会出现在仓库地址里，建议别用中文）
3. **开源 / 私有**：建议选「私有」。库存含采购信息，不该公开；以后想分享再改公开
4. **必须勾选「使用 Readme 文件初始化这个仓库」**
   > ⚠️ 关键：软件首次同步执行 `git clone --branch main`。**空仓库没有 main 分支会直接 clone 失败**（报 `Remote branch main not found`）。勾选初始化后远端自带 main 分支，一劳永逸。
5. 点「创建」，进入仓库页
6. 点页面上的「克隆/下载」→ 复制 **HTTPS** 地址，形如：
   ```text
   https://gitee.com/<你的用户名>/<仓库名>.git
   ```
   例如 `https://gitee.com/zhangsan/parts-warehouse-sync.git`

> Gitee 用户名不一定是显示名：在「设置 → 账号资料」里看 login 字段，仓库地址里的那一段才是。

### 2.2 在 GitHub 创建（境外/异地备份）

1. 登录 [github.com](https://github.com) → 右上角「+」→「New repository」
2. **Repository name**：英文，例如 `parts-warehouse-sync`
3. **Public / Private**：建议 Private
4. **必须勾选 `Add a README file`**（理由同上：保证远端有 main 分支）
5. 创建后点绿色「Code」按钮 → 复制 **HTTPS** 地址：
   ```text
   https://github.com/<你的用户名>/<仓库名>.git
   ```

### 2.3 双平台怎么选

| 场景 | 选哪个 |
| --- | --- |
| 国内主力使用 | Gitee（连接稳定） |
| 境外 / 异地备份 | GitHub |
| GitHub 频繁连接重置 | 换 Gitee，或改用 SSH 地址（见 3.3） |

两个平台可以在软件里**同时配置、一键切换**（设置 → 线上同步 → 同步平台）。

## 3. 配置电脑凭据（Windows）

软件本身**不保存任何 Token**，认证交给系统 Git（Git Credential Manager / SSH）。需要先保证这台电脑 push/fetch 远端免输入。

### 3.1 确认 Git 已安装

装过 Git for Windows 即可（自带 Git Credential Manager）。检查方法：开始菜单搜 Git Bash，打开后输入：

```bash
git --version
```

### 3.2 推荐：私人令牌（PAT）+ 系统凭据管理器

**Gitee 生成令牌：**
1. 头像 →「设置」→「安全设置」→「私人令牌」→「生成新令牌」
2. 勾选 `projects` 权限（仓库读写），复制生成的令牌（只显示一次）

**GitHub 生成令牌：**
1. 头像 → Settings → Developer settings → Personal access tokens → Generate new token
2. 勾选 `repo` 权限，复制令牌

**首次使用时输入：**

第一次在软件里「检测远端更新 / 同步远端 / 提交账本」时，会弹出 Git 登录窗口：

- Gitee：用户名填 **Gitee login（不是邮箱）**，密码填 **令牌**（不是登录密码）
- GitHub：选「Sign in with your browser」网页登录，或用户名 + 令牌

输入一次后令牌存入 **Windows 凭据管理器**，此后不再询问。

> 凭据只在系统里，绝不写进设置文件 / 仓库地址 / 代码 / 聊天记录。

### 3.3 备选：SSH（GitHub 不稳时更可靠）

1. Git Bash 里生成密钥：`ssh-keygen -t ed25519 -C "你的邮箱"`（一路回车）
2. 复制公钥：`cat ~/.ssh/id_ed25519.pub`
3. 平台设置里粘贴公钥：Gitee「设置 → SSH 公钥」/ GitHub「Settings → SSH and GPG keys」
4. 仓库地址改用 SSH 格式：
   - Gitee：`git@gitee.com:<用户名>/<仓库名>.git`
   - GitHub：`git@github.com:<用户名>/<仓库名>.git`

## 4. 软件内设置（一步步）

### 4.1 打开设置

侧栏点「⚙ 设置」→ 顶部页签选「**线上同步**」。

### 4.2 选平台 + 填配置

1. **同步平台**：`Gitee（国内，推荐）` 或 `Git / GitHub`。切换立即保存生效，**两个平台的配置各自独立**（可以都填好，随时切换）。
2. 在对应平台的设置块（🌐 Gitee 设置 / 🔄 Git 设置）里填：

   | 字段 | 填什么 | 示例 |
   | --- | --- | --- |
   | 同步用户名 | 操作者标识，会记进每条上传记录 | 张三 |
   | 仓库地址 | 第 2 步复制的地址（`.git` 结尾） | `https://gitee.com/zhangsan/parts-warehouse-sync.git` |
   | 本地同步目录 | 点「📁 浏览…」选一个**空目录**，软件在这里放仓库副本 | `C:\Users\张三\AppData\Local\parts-warehouse-sync` |
   | 分支 | 保持默认 `main` | main |
   | 事件目录 | 保持默认 `events` | events |

3. 勾选「**启用 Gitee 增量同步**」（或 Git）→ 点「**保存 Gitee 配置**」（或 Git）。
4. 点「**🔍 检查配置**」：提示"Git 配置格式已填写"即通过。
5. 点「**🔄 检测远端更新**」：首次会执行 clone（此时弹 Git 登录窗，按第 3 节输入）。看到"已首次克隆 Git 仓库"即成功。

### 4.3 线上同步页（侧栏「⇄ 线上同步」）

页面分两块，语义完全不同：

| 面板 | 按钮 | 作用 |
| --- | --- | --- |
| 左栏「读取内容」 | （自动显示） | 本次拉取到的**远端新增事件**与已读状态 |
| 右栏「远端同步」 | `🔄 同步远端` | fetch + 读取新增事件，**不会**上传本机账本 |
| 右栏「提交本机账本」 | `⬆ 提交所选账本记录` | 把勾选的本机账本记录**推送**到远端（可重复提交） |

**首次跑通流程：**

```text
设置填好 → 检查配置 → 检测远端更新（clone）
→ 先在软件里做一次入库/取出（产生本机账本记录）
→ 线上同步页 → 勾选记录 → 提交所选账本记录
→ 看到事件文件名回显 = 同步成功
```

### 4.4 账本记录徽标

| 徽标 | 含义 |
| --- | --- |
| 🖥️ 本机 | 本机产生，尚未提交（pending） |
| ⬆ 已提交 | 已推送到线上（submitted，可再次提交生成新事件） |
| 🌐 线上 | 从远端读回的记录，**只读**（不渲染撤回/勾选） |

## 5. 同步规则（重要）

- **浏览不联网**：看库存、分类、账本不访问远端，界面不卡
- **写入前检查**：只有真正改库存的确认动作（入库 / 取出 / 保存表 / 撤回等）前检查一次远端状态；检查失败会**阻止写入**并提示，不会静默覆盖
- **事件粒度**：一条账本记录 = 一条事件文件（明细全放 `items[]`），不按明细拆碎
- **可重复提交**：已提交记录勾选后再提交，会生成新的全局事件 ID，不覆盖历史
- **线上事件只读**：读回的远端事件写入账本展示（origin=remote），当前版本**不自动改库存**（重放到库存是后续版本）
- **凭据不进仓库**：Token / 密码只存在 Windows 凭据管理器

## 6. 常见问题（FAQ）

**Q: clone 报 `Remote branch main not found in upstream origin`？**
A: 远端仓库是空仓库（没初始化）。回 Gitee/GitHub 网页，仓库设置里勾选 README 初始化，或推送一个初始提交后再同步。

**Q: 提示「本地同步目录非空且不是 Git 仓库」？**
A: 换一个空目录，或先把该目录清空再重试。

**Q: GitHub 报 `Recv failure: Connection was reset` / 一直转圈？**
A: 国内网络对 GitHub 间歇性 TCP 重置，与仓库/权限无关。改选 Gitee 平台，或把地址换成 SSH 格式（见 3.3）。

**Q: 弹窗要输什么密码？**
A: 输私人令牌（PAT），不是平台登录密码。Gitee 用户名填 login（不是邮箱）。

**Q: 提交账本后提示 nothing to commit？**
A: 正常，属于幂等重试场景，不是错误。

**Q: 换电脑怎么继续同步？**
A: 新电脑按第 4 节填**同一个仓库地址** → 检查配置 → 同步远端（读取历史事件）。注意新电脑首次也要走一遍凭据配置。

**Q: 仓库地址填错了能改吗？**
A: 直接在设置里改「仓库地址」再保存即可；本地同步目录建议一并换新（或清空原目录）。

**Q: 设置文件在哪？排查用**
A: 打包版在 exe 旁 `data/settings.json`，源码版在项目 `data/settings.json`。同步相关字段：`sync_provider`（gitee/git）+ `gitee_sync` / `git_sync` 两个独立配置段（enabled / remote_url / local_dir / branch / events_dir / username）。**凭据不在这里**，在 Windows 凭据管理器。
